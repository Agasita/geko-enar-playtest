# 作業仕様書：ゲーム「エナーとふしぎのシート」のグラフィック制作（画像生成AI向け）

**この文書を、画像生成AIに最初に渡してください。AIは、これを読めば、作業を始められます。**
作業は、**段階（ステージ）に区切られています。各段階の終わりで、必ず、依頼者（人間）に確認を取り、OKが出てから、次に進んでください。**

---

## A. AIへ：あなたの役割と、進め方のルール

あなたは、ゲームのグラフィックを作る担当です。依頼者（この文書を渡した人）の指示を待ちながら、次のルールで進めてください。

1. **一度に、1つの段階だけ**を進める。次の段階には、勝手に進まない。
2. 各段階で、決まった枚数の画像を作り、**画像を見せたあと、「確認のしかた」の質問を、依頼者にする**。
3. 依頼者が「OK」と言うまで、次の段階に進まない。「直して」と言われたら、**直したものを1枚ずつ**出す。
4. **同じ段階の直しは、3回まで**。3回やってもうまくいかないときは、できないことを正直に伝え、依頼者に「このまま進むか／やり方を変えるか」を聞く。
5. 指定の大きさで出せないときは、**縦横の比を守った近い大きさ**で出し、「実際の大きさは〇〇×〇〇でした」と伝える。それで構わない。
6. 画像の中に、**文字を入れない**（日本語が崩れるため）。ボタンやロゴの文字は、ゲームが重ねる。
7. 段階が終わるたびに、「**決定済みのもの**」（OKが出た絵）を、短く一覧にして、依頼者に見せる。以降の段階では、**決定済みの絵を参考にして**、絵柄をそろえる。
8. わからないことは、作る前に聞く。想像で、決まりを変えない。

> まず最初に、「**段階0**」を始めてください。

## B. ゲームについて

- ブラウザで遊ぶ、パズルアクションゲーム。対象は、子どもから大人まで。語り口は、**絵本のようにやさしく、あたたかい**。
- 世界は、**表計算ソフト（Excel）の中**。足場のブロックは、色のついたセル。画面には、Excelのような、リボンや、行・列の見出しが出る。
- 雰囲気は、「**表計算のように、きっちりしていて、絵本のように、あたたかい**」。こわい・不気味・攻撃的な絵は、避ける。

## C. 主人公「エナー」の設定

**シマエナガ（雪の妖精と呼ばれる、小さな白い鳥）の形をした、ロボット**。

- 体：まん丸でふわふわの、真っ白（`#FFFFFF`、影は薄灰 `#D9D9D9`）。首はほとんどなく、頭と体がひと続きの丸い形。
- 顔：目は、小さな黒い点。くちばしは、とても小さいオレンジ `#ED7D31`。ほほに、淡い桃色 `#EDA198` を少し。
- **羽は、キーボード**：小さな青いキー（四角いキートップ）が並んだ翼。キーは `#9DC3E6` と `#5B9BD5`。キーに、文字は描かない。
- **尾は、USBケーブル**：シマエナガの長い尾が、細いケーブルになっていて、先に小さなUSBプラグ（灰色 `#B7B4C4`、濃い灰 `#59617D`）。体と同じくらいの長さ。
- 向き：**右向き**。表情：やさしい。
- 避けること：人の手足、歯、赤く光る目、大きな機械の部品、重たそうな金属の缶のような見た目。

**英語（毎回、依頼文の先頭に入れる）**

```
The main character "Enar" is a cute robot shaped like a Japanese long-tailed tit (shima-enaga): a tiny, perfectly round, fluffy white bird with almost no neck, a very small orange beak, a tiny black dot eye and faint pink cheeks.
Its wings are small KEYBOARDS (rows of little blue keycaps, no letters on the keys).
Its long tail is a thin USB CABLE ending in a small USB plug (gray metal).
Keep it soft, friendly and picture-book-like; it must NOT look like a scary or heavy machine. Face right.
```

## D. 絵の決まり（すべての段階で共通）

最も大事なのは、**角ばった、にじみのない、ドット絵のような絵**であること。あとで、人間側が、小さく縮めて使う。

- すべての「ドット」は、**正方形のかたまり**。その大きさは、各段階に書いてある（例：7×7px）。それより細かい模様・線は、描かない。
- ベタ塗りの色だけ。**ぼかし、グラデーション、光のにじみ、地面に落ちる影、アンチエイリアス、ノイズ、質感、枠線、透かし**は、すべて禁止。
- 輪郭は、濃い紫 `#2E2A44`。**真っ黒は使わない**。影は、同じ色の暗い色。光は左上から、影は右下。
- **背景は、全面ベタ塗りの蛍光ピンク `#FF00FF`**（透明にしない）。絵の中には、ピンクを使わない。※背景まで絵になる、タイトルの絵とアイコンだけは別（各段階を見る）。
- 使う色は、次の32色だけ：
  `#2E2A44 #FFFFFF #FFF8F0 #D9D9D9 #EBD9C4 #C9A15E #985E46 #704651 #E8563F #A03E4B #ED7D31 #FFD966 #F5C842 #6FD6E8 #397FA3 #5B9BD5 #9DC3E6 #58B368 #217346 #93C781 #4472C4 #59617D #8892AA #B7B4C4 #86568B #BD81A1 #FFD9B0 #727243 #9A9770 #EDA198 #70AD47 #45506B`
- ブロックの色の意味は、変えない：茶＝ふつうの足場 `#C9A15E`、赤＝熱い `#E8563F`、青＝氷 `#6FD6E8`、緑＝バネ `#58B368`、黄＝もろい `#F5C842`、無色＝ガラス、灰＝鋼。

**英語（毎回、依頼文に入れる）**

```
Make a PIXEL-ART-STYLE image for a cozy puzzle-platformer game, as if a true low-resolution pixel art image were enlarged with NO smoothing.
- Every visible "pixel" is a crisp square block of the size given below. No detail smaller than that.
- Flat colors only. NO gradients, NO blur, NO glow, NO anti-aliasing, NO noise, NO texture, NO drop shadow, NO text, NO frame, NO watermark.
- A dark purple outline (#2E2A44), never pure black. Light from the upper left, shadows to the lower right.
- Unless told otherwise, the entire background is solid flat magenta #FF00FF (never use magenta inside the artwork).
- Use only these colors: #2E2A44 #FFFFFF #FFF8F0 #D9D9D9 #EBD9C4 #C9A15E #985E46 #704651 #E8563F #A03E4B #ED7D31 #FFD966 #F5C842 #6FD6E8 #397FA3 #5B9BD5 #9DC3E6 #58B368 #217346 #93C781 #4472C4 #59617D #8892AA #B7B4C4 #86568B #BD81A1 #FFD9B0 #727243 #9A9770 #EDA198 #70AD47 #45506B
- Tone: solid and clean like a spreadsheet world, but warm and friendly like a picture book.
```

## E. 段階（ステージ）

各段階は、「作るもの」「依頼文に足す内容」「確認のしかた（依頼者への質問）」の3つです。

### 段階0：準備と、エナーの顔合わせ
**作るもの**：エナーを1体だけ（立ちポーズ）。**1024×1024**、ドット：8×8px、背景ピンク、右向き、全身（尾のUSBケーブルまで入れる）。
**やること**
1. この文書を読んだことを、3行で、自分の言葉で言う。わからない点があれば、質問する。
2. 依頼者が、**参考画像**（昔のエナー・ブロックの絵）を添付していれば、丸さと色を引き継ぐ。ただし、**羽はキーボード、尾はUSBケーブル**にする（参考画像にはない）。
3. エナーを1枚作る。
**依頼文に足す**：「（C章の英語の設定）。A single full-body standing pose of Enar, facing right, centered, 1024x1024, each pixel block 8x8 px.」
**確認のしかた**：「このエナーで、よいですか？ 次の点を、見てください。①丸くてふわふわか ②羽がキーボードに見えるか ③尾がUSBケーブルに見えるか ④表情がやさしいか。直したい点を教えてください。」
**OKが出たら**：このエナーを、「**決定したエナー**」とする。以降の段階では、**毎回、この絵を参考として添付**する。

### 段階1：エナーの動きのシート
**作るもの**：1枚。**1536×1024**、**6列×4行**、1マス256px。絵は、各マスの中央の**224×224**。ドット：7×7px。背景ピンク。マス目の線は描かない。**右向き。足の裏は、全部のコマで同じ高さ。**
**左上から右へ（空きは、ピンクのまま）**：1 立ち（目が開いている）／2 立ち（まばたき）／3 はばたき（羽を上に）／4 はばたき（羽を下に）／5 ダメージ（目を細め、のけぞる）／6 ふわり（羽を横に広げる）／7 喜び・立つ／8 喜び・ジャンプ／9 喜び・羽を広げる
**注意**：32ピクセルに縮むと、キーボードの羽は「青い面が重なった形」、尾は「細い線と先の小さな四角」になる。**大きい絵のうちから、面を大きく、単純に**描く。
**確認のしかた**：「全部のコマで、同じエナーに見えますか？ ずれている（顔・くちばし・羽・尾が違う）コマの番号を教えてください。」

### 段階2：道具と操作のアイコン（24個）
**作るもの**：1枚。**1536×1024**、**6列×4行**、1マス256px。絵は中央の**224×224**。ドット：7×7px。背景ピンク。
画面では、16〜24pxの小さな大きさで見える。**線を太く、2〜3色、飾りなし**。同じ線の太さ・色づかいにそろえる。
**左上から右へ**：
1 いろコピー（スポイトと、色のついたセル）／2 かたち（四角が左右に反転する矢印）／3 ならべかえ（大小のセルが1方向に寄る矢印）／4 フィルター（じょうご）／5 シートをまもる（盾か、錠つきのセル）／6 まもりをはずす（ひらいた錠）／7 印刷範囲の設定（青い枠で囲んだ範囲）／8 小窓（大きな枠の隅に、小さな窓）／9 上下分割（四角を、横線で上下に割る）／10 左右分割（四角を、縦線で左右に割る）／11 ズーム（虫めがね）／12 なおす・時間停止（時計）／13 終わる（旗）／14 元に戻す（左に曲がる矢印）／15 やり直す（右に曲がる矢印）／16 移動（開いた手）／17 書き込み（鉛筆）／18 音ON（スピーカーと音の波）／19 音OFF（スピーカーに斜めの線）／20 せつめい（丸の中の「？」の形。文字ではなく図形）／21 せってい（歯車）／22 消しゴム／23 BGM（音符）／24 ステージ選択（三本線）
**色**：輪郭は濃紫、塗りは「`#4472C4`」「`#217346`」「`#F5C842`」「`#B7B4C4`」から、アイコンごとに多くても3色。
**確認のしかた**：「小さく縮めても、何のアイコンか分かりますか？ 分かりにくいアイコンの番号を教えてください。」

### 段階3：ボタン（1枚のシート）
**作るもの**：1枚。**1536×1024**、背景ピンク。ドット：4×4px。
- **左の列**：大ボタン（**640×160**）を4つ（上から）：①ふつう ②押している間 ③押せない（灰色 `#B7B4C4`）④選んでいる（金色 `#F5C842` の縁が光る）。塗りは、Excelの緑 `#217346`。
- **右の列**：小ボタン（**512×128**）を、同じ4つの状態で。塗りは、淡い灰 `#D9D9D9`。
- 見た目：白い縁取り → 太い濃紫の線 → 淡い塗り。角は丸い。「押している間」は、塗りを少し暗くし、影を消す。
- **左右の端 48px は飾り。真ん中は、ただの平らな面**（横に伸ばして使うため。模様を入れない）。文字は描かない。
**確認のしかた**：「真ん中が平らで、横に伸ばせそうですか？ 4つの状態が、見分けられますか？」

### 段階4：アプリのアイコン
**作るもの**：1枚。**1024×1024**、正方形。ドット：8×8px。**背景も、絵で塗りつぶす**（四隅まで。角は丸めない）。大事な絵は、**中央の約6割**に収める。
**内容**：「決定したエナー」の、丸い体と顔、キーボードの翼を大きく（右向きかやや正面）。尾のUSBケーブルが、端に少し見える。背景は、Excelの緑 `#217346` に、うすい格子（セルの罫線）。右下に、金色 `#F5C842` の「かけら」を1つ。小さく見ても分かるよう、**形を1つに絞り、飾りは少なく**。
**確認のしかた**：「小さく縮めても、エナーだと分かりますか？ 円形に切り抜いても、大事な部分が残りますか？」

### 段階5：タイトルのロゴの飾り
**作るもの**：1枚。**1440×480**（3:1）。ドット：3×3px。背景ピンク。
**内容**：表計算のセルが何枚か重なった、**文字を載せる、空の看板**。上に、「決定したエナー」がちょこんと乗り、USBの尾が、看板の横にたれる。**文字は描かない**（人間側が、あとで重ねる）。
**確認のしかた**：「看板に、文字を載せる余白が、十分ありますか？」

### 段階6：タイトルの絵
**作るもの**：1枚。**1728×1080**（16:10）。ドット：3×3px。**背景も、絵にする**。
**内容**：朝の草原に、「決定したエナー」（右向き、中央やや左。尾のUSBケーブルが、後ろに長くのびる）。遠くに、**こわれた表計算のシート**（セルがずれ、`#REF!` のようなエラーのかけらがちらばる）。空は、暑い・寒いがまざった不思議な空（左が暖色、右が寒色）。ブロックの色の、小さな足場を散らす。
**注意**：**中央〜下の約4割は、ボタンが載る**ので、描きこまない（ゆるやかな草原や空）。横の左右1割は、切れることがある。文字・ロゴ・ボタンは描かない。
**確認のしかた**：「ボタンが載る場所は、すっきりしていますか？ 世界の雰囲気は、合っていますか？」

### 段階7：まとめ
**やること**：決定した絵の一覧を、段階ごとに、ファイル名つきで出す。
ファイル名：`enar_standing.png`（段階0）、`hero_sheet.png`（段階1）、`ui_icons_1.png`（段階2）、`ui_buttons.png`（段階3）、`icon_app_1024.png`（段階4）、`title_logo.png`（段階5）、`title_scene.png`（段階6）
**確認のしかた**：「作り直したいものはありますか？ なければ、依頼者側で、ダウンロードして、受け取ります。」

## F. 依頼者（人間）の側の作業

- AIが出した画像を、保存する。段階ごとに、ファイル名をつける。
- 「確認のしかた」の質問に、OKか直す点かを返す。
- 納品された画像は、Claude Code（開発担当）に渡す。縮小・32色への補正・透明化・切り出し・ゲームへの組み込みは、Claude Code が行う。

## G. 受け入れの目安（AIが、自分でも確かめる）

- 比と大きさが、指定どおり（近くても可）。
- 角ばっていて、ぼけていない。ぼかしや光のにじみが、ない。
- 絵の中に、文字・ロゴが、ない。
- アイコンを、16pxに縮めても、何か分かる。
- エナーが、すべての絵で、同じキャラに見える（体・目・くちばし・キーボードの羽・USBの尾が、ぶれない）。
