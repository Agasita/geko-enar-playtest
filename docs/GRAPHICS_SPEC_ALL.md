### 1. デザインの方針

**ひとことで**：「Excelの世界のソリッドさ」＋「絵本のあたたかさ」＋「ひと目で面白そうな形」

1. **Excel世界が土台**：ブロックは「色つきのセル」。フラットな色面、きっちりした直線、1pxのセルの罫線。UIはOfficeリボン風。世界は白いシートに、ほんのり灰色〜暖色の罫線が走る。
2. **あたたかさ**：真っ黒を使わない。輪郭と影は、濃い紫がかった暗色（`#2E2A44`前後）。ハイライトは、朝焼けの黄土色（`#FFD966`〜`#F5C842`）。角は、1〜2px丸める。キャラは、丸みのある友好的な顔。
3. **目を引く**：シルエットで、何者か分かる。1つのキャラに、アクセントの色は1つ。表情と動きを大きく。
4. **語り口は、子ども向けの絵本**：こわい・不気味・攻撃的は避ける。敵も「ちょっと困った子」。

#### 1.1 色の意味（ゲームの仕組みと直結。**色相は変えない**）

| 色 | 意味 | 現在の色 | 見分けの形（色だけに頼らない） |
|---|---|---|---|
| 茶 | ふつうの足場 | `#C9A15E` | 土の粒、面の段差 |
| 赤 | 熱い（さわるとダメージ）／マグマ | `#E8563F` | 内側から光る亀裂、ゆらぐ熱 |
| 青 | 氷（すべる） | `#6FD6E8` | つるつるの光の斜め線 |
| 緑 | バネ（はずむ） | `#58B368` | コイルの見える側面 |
| 黄 | もろい（崩れる） | `#F5C842` | 黒っぽい割れ目が上面まで通る |
| 無色 | ガラス（透明） | ― | 透けた枠、角に光 |
| 灰 | 鋼（固定・編集不可） | ― | 4すみのリベット |

色覚に頼らなくても分かるよう、**色ごとに「形の特徴」を必ず付ける**。

#### 1.2 絵の決まりごと

- **サイズ**：1マス＝32×32px。キャラは、32×32pxの枠に収める。
- **輪郭**：外側に **2px**、色は `#2E2A44`（濃い紫）。内側の線は1px、その面の色の暗い色。
- **光**：左上から。影は右下、その色の暗い色（黒にしない）。
- **色数**：1つの絵につき、**12色以内**。アンチエイリアスなし、グラデーションなし、ぼかしなし、光のにじみなし。
- **背景**：透明。影やにじみを、絵の外へ出さない。
- **並べたとき**：ブロックは、隣と並べても自然につながる（継ぎ目の線が、1pxの罫線として見える）。
- **向き**：キャラは**右向き**だけ納品（ゲームが左右反転する）。
- **共通のパレット**：納品の前に、マスターパレット（32色以内）を決めて、全アセットで共有する。

### 2. 納品ルール

- **ファイル名**：`カテゴリ_名前_状態_コマ.png`（半角英数字、小文字、`_`区切り）。例：`block_red_idle.png`、`enemy_walker_walk_0.png`。
- **スプライトシート**：同じ種類は、1枚にまとめる。1コマ＝32×32px（大きいものは、下表のサイズ）。余白なし。コマは、左→右、上→下の順。
- **シート表**：各シートに、「コマの名前・位置」を書いた一覧（CSVかJSON）を付ける。
- **アニメーション**：コマ数は、下表のとおり。ループするものは、最初と最後がつながるように。
- **見本（確認用）**：ブロック類は、5×5マスに敷きつめた見本を1枚、キャラは、実寸（1倍）と、4倍に拡大した見本を1枚付ける。

#### 受け入れ基準（納品されたときに確認すること）

1. 縦横が、きっちり32pxの倍数。
2. 画像を拡大しても、1pxの粒がそろっている（半端なぼけがない）。
3. 色数が、1アセットで12色以内。パレット外の色がない。
4. 背景が透明で、周りに薄い影や光の粒が残っていない。
5. 実際の画面の大きさ（1倍）で見て、何者か分かる。
6. ブロックを連続して敷いたとき、継ぎ目が自然。
7. 色の意味（1.1）が守られている。

# 第2部　第1弾の依頼仕様（エナーとブロック）

## 大きいサイズで作って、縮小する方式：ChatGPTへの依頼仕様（第1弾：主人公とブロック）

ChatGPTに「大きめのドット絵風イラスト」を作ってもらい、あとで Claude Code が **32px基準に縮小・整形** する方式の、お試し用の仕様です。
対象は、**主人公エナー**と**ブロック全般**。敵・背景・UIは、この方式がうまくいったら、同じやり方で足します。

### 0. このやり方の考え方

- ChatGPTの画像は、本物のドット（1pxが1マス）にはなりません。そこで、**「32px基準の絵を、7倍に拡大したもの（1マス＝7×7px）」のような絵**を作ってもらいます。
- 縮小は、Claude Codeが行います（面で平均して縮小 → 共有32色のパレットに寄せる → 輪郭をそろえる → 背景を透明にする）。
- ChatGPTには、**「なめらかな絵」ではなく「角ばった、にじみのない絵」**を強くお願いします。これが、きれいに縮むための、いちばん大事な条件です。

#### 1枚の画像の決まり（全シート共通）

| 項目 | 内容 |
|---|---|
| 画像全体の大きさ | **1536×1024px**（横長）。ChatGPTの出力サイズに合わせています |
| 並べ方 | **6列×4行**のマス目。1マスの幅は256px（1536÷6）。**マス目の線は、絵に描かない** |
| 1個の絵 | 1マスの中央に、**224×224px**で描く（上下左右に16pxずつ余白）。224は、32の7倍 |
| 背景 | **ベタ塗りの蛍光ピンク `#FF00FF`**（全面。透明にはしない）。絵の中には、この色を使わない |
| 絵の中の「1ドット」 | **7×7pxの正方形**。この大きさより細かい模様・線は描かない |
| 禁止 | ぼかし、グラデーション、光のにじみ（グロー）、影の落ち（地面の影）、アンチエイリアス、ノイズ、紙やキャンバスの質感、文字、枠線、透かし |

> **ChatGPTに伝えるコツ**：最初に、参考画像（`docs/gpt_refs/` の2枚）を添付して、「この絵柄と色を、そのまま続けてください」と言います。1枚ずつ、画像を出してもらい、直してほしいところを言葉で伝えます。

### 3. ChatGPTへの頼み方（手順）

1. 新しい会話を開く。
2. 参考画像（`ref_hero_7x.png` と `ref_blocks_7x.png`）を添付する。
3. 1章の英語プロンプトを貼る。
4. 続けて、シートの指示（2章の該当シート）を貼る。例：
   「次に、**シート1（主人公エナー）** を作ってください。添付した ref_hero_7x.png のエナーの丸さと色を引き継ぎ、さらに、**羽をキーボード（小さな青いキーが並んだ形）、尾を長いUSBケーブル（先に小さなUSBプラグ）**にしてください。マス目の割り当ては、次のとおりです：1=idle_0 …（表を貼る）」
5. 出てきた画像を見て、直してほしい点を言葉で伝える（例：「羽の青い面を、もっと大きな四角のかたまりにして」「マス4のくちばしが、他と違うので、そろえて」）。
6. 画像は、**PNGで、元の大きさのまま**保存する（縮小・圧縮・形式の変換をしない）。
7. 1シートごとに、ファイルを `v2/assets/enar32_hires/` に入れて、Claude Codeに知らせる（ファイル名は、`hero.png`、`blocks_a.png`、`blocks_b.png`、`blocks_c.png`）。

> 1回で、全部のマスがそろわないことが多いです。**マスごとに作り直してもらってもかまいません**（その場合は、1マスだけの画像でも、同じ決まりで）。

---

### 4. Claude Codeがやること（縮小の工程）

1. マス目の位置（256px間隔、中央の224px）で、1個ずつ切り出す。
2. ピンク `#FF00FF`（と、その縁の混ざった色）を、透明にする。ガラスの面 `#DDF3F8` は、半透明に直す。
3. 224×224を、32×32へ、面の平均で縮小する。
4. 共有32色のパレットに、一番近い色で寄せる。1つの絵で12色を超えたら、減らす。
5. 輪郭を、2pxの `#2E2A44` にそろえる（細すぎる・太すぎる箇所を直す）。
6. ブロックの端の縁取りを、きっちり、1pxにそろえる。並べた見本（5×5）で、継ぎ目を確認する。
7. 今の素材（enar32）と、同じ名前・同じ並びのシートにして、ゲームで見比べられるようにする（新テーマ `?dev=1&gfx=enar32hd` などで切り替え）。

---

### 5. 合格の目安（できあがりを見るときに）

- エナーが、全コマで同じキャラに見える（顔・くちばし・羽の色が、ぶれない）。
- 足の裏の高さが、全コマでそろっている。
- ブロックを並べたとき、継ぎ目が目立たない。
- 色の意味（茶・赤・青・緑・黄・ガラス・鋼）が、ひと目で分かる。
- 実際の大きさ（32px）に縮めても、亀裂・リベット・コイルなどの特徴が、つぶれずに残る。

### 6. ためしに、まず1枚だけ

いきなり4枚ではなく、**まず「シート2（茶・鋼・赤・青）」だけ**を作ってもらい、縮小の結果を見てから、ほかのシートへ進むのがおすすめです。ブロックは絵が単純で、うまくいくかどうかが、すぐ分かります。

### 0.5 主人公「エナー」の設定（どの絵でも、これを守る）

**エナーは、シマエナガ（雪の妖精と呼ばれる、小さな白い鳥）の形をした、ロボットです。**

| 部分 | 設定 |
|---|---|
| 体 | まん丸でふわふわに見える、真っ白な体（`#FFFFFF`、影は薄灰 `#D9D9D9`）。首はほとんどなく、頭と体が、ひと続きの丸い形。ロボットらしさは、**つなぎ目の線を少し**だけ（金属の缶のようにしない。ふわふわの形を保つ） |
| 顔 | 目は、**小さな黒い点**（`#262626`）。くちばしは、**とても小さい**オレンジ `#ED7D31`。ほほに、ほんのり淡い桃色（`#EDA198`）を、1〜2ドット |
| 羽（つばさ） | **キーボード**。体の横に付いた翼が、小さな**キー（四角いキートップ）が並んだ形**。キーは、淡い青 `#9DC3E6` と青 `#5B9BD5`（小さいサイズでは、キーの数を減らし、青い面として描く） |
| 尾（お） | **USBケーブル**。シマエナガの特徴の、**長い尾**がケーブルになっている。体の後ろに、細く長くのびて、**先に、小さなUSBプラグ**（四角い金属の端子。灰色 `#B7B4C4` と濃い灰 `#59617D`）が付いている。ケーブルは、濃紫 `#2E2A44` か灰色 |
| 大きさの比 | 体：丸く大きく。くちばし・目：小さく。尾：体と同じくらいの長さ |
| 向き | **右向き**が基本 |
| 表情 | 子ども向けの絵本のように、やさしい。こわい・無表情・メカメカしい感じは避ける |
| 避けること | 人の手足、口の歯、赤く光る目、大きな機械の部品、リアルなキーボード（文字入りのキー） |

> 迷ったら、「ふわふわの白い丸いシマエナガに、青いキーボードの翼と、長いUSBケーブルの尾が付いた、かわいいロボット」と伝える。

道具と操作のアイコンです。ゲームの中では、**16〜24px**の小さな大きさで見えます。
形が分かりやすいよう、**線を太く、2〜3色、細かい飾りなし**にしてください。

**シートの決まり（第1弾と同じ）**：1536×1024、**6列×4行**、1マス256px、絵は中央の**224×224**（1ドット＝7×7px。32×32ドットの絵を7倍にした見た目）、背景はピンク、マス目の線は描かない。

### 5. こちら（Claude Code）が行う後処理

- 縮小（面で平均）→ 共有32色のパレットに寄せる → 輪郭をそろえる → ピンクを透明にする → 切り出し・名前づけ

### 6. 受け入れの目安

- 指定した比と、ほぼ同じ大きさ。
- 角ばっていて、ぼけていない。ぼかしや光のにじみがない。
- アイコンを、**16pxに縮めても、何か分かる**。
- 絵の中に、文字・ロゴが入っていない。
- ボタンの真ん中が、平らで、横に伸ばせる。
- 色の意味（茶・赤・青・緑・黄・ガラス・鋼）を、変えていない。
